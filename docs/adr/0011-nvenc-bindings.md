# ADR-0011: прямой NVENC — свои привязки к API 12.0

Статус: принято (2026-10-30).

## Контекст

ТЗ §9.1: NVENC — динамическая загрузка `nvEncodeAPI64.dll`, привязки к Video Codec SDK (заголовки
MIT), вход — D3D11-текстура NV12/P010 без копий, пресеты P1–P7, тюнинг, lookahead, AQ.
Недоступный энкодер показывается с причиной («устаревший драйвер, нужна версия ≥ …»).

## Решение

- Привязки — свои, сгенерированы `bindgen` 0.73 из `nvEncodeAPI.h` (FFmpeg/nv-codec-headers, тег
  `n12.0.16.1`, MIT) для `x86_64-pc-windows-msvc` и лежат в `crates/cs-encode/src/nvenc/sys.rs`.
  Раскладку считает clang для цели MSVC; размеры и смещения структур проверяются при компиляции.
  GUID (в заголовке — `static const`) и версии структур (макросы) заданы вручную внизу файла.
- Версия API — 12.0: драйвер NVIDIA ≥ 522.25 (октябрь 2022), есть всё из ТЗ (P1–P7, тюнинг,
  AV1 на RTX 40+). Драйвер принимает старшие версии API только начиная со своей; новее — нет.
- Библиотека грузится `LoadLibraryW` во время работы; нет драйвера или он старый — энкодер
  «недоступен» с причиной, автовыбор переходит к Media Foundation.
- Синхронный режим, кадр регистрируется один раз (пул конвертера) и отображается на время
  кодирования. При анализе наперёд пакеты забираются с отставанием на его глубину (как
  `NvEncoder` из SDK): «кадр принят» не значит, что готовы пакеты всех поданных кадров.
- Пресеты «высокое качество» сами включают анализ наперёд — он выключается явно, если не нужен.
- B-кадры (до 4) не опорные: время декодирования — время подачи кадров со сдвигом в один кадр;
  перепаковка в MP4 пишет `ctts` и сдвиг в `elst` (2.11).

Перегенерация (нужны `libclang` и `bindgen-cli`):

```
bindgen nvEncodeAPI.h -o sys.rs --allowlist-type 'NV_ENC.*|_NV_ENC.*|NVENCSTATUS|PNVENC.*|NV_ENCODE_API_FUNCTION_LIST' \
  --allowlist-var 'NV_ENC_.*|NVENCAPI_.*' --blocklist-var '.*_GUID' --blocklist-type '_GUID|GUID' \
  --raw-line 'pub type GUID = windows_core::GUID;' --default-enum-style consts --no-doc-comments --use-core \
  -- --target=x86_64-pc-windows-msvc
```

## Альтернативы

- Крейт `nvidia-video-codec-sdk`: статическая компоновка с библиотекой NVENC и зависимость от
  CUDA (`cudarc`), без D3D11-пути — не подходит.
- Ручные привязки: много структур с битовыми полями и резервами — тихие ошибки раскладки.
- NVENC через Media Foundation (было до этого решения): нет пресетов P1–P7, тюнинга, lookahead.

## Последствия

- Найдено при проверке: структура `NV_ENC_LOCK_BITSTREAM` версии 2 (так в nv-codec-headers
  12.0.16) драйвером при сессии API 12.0 отвергается (`NV_ENC_ERR_INVALID_PARAM`); используется
  версия 1 — раскладка та же.
- Тест на GPU (`cargo test -p cs-encode --test nvenc_gpu -- --ignored`): 120 кадров → 120 пакетов,
  SPS/PPS в ключевых кадрах, GOP; поток декодируется `ffmpeg` без ошибок.
