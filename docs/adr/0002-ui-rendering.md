# ADR-0002: UI — egui на собственном D3D11-рендерере, Win32-окно и DirectComposition

**Контекст.** §5.2 п.2: egui поверх *того же* D3D11-устройства, что и компоновщик/энкодеры, превью — нативная
текстура без копий; решение «готовый крейт или свой рендерер» — в ADR. §11.2 требует окно без системной
рамки со Snap Layouts (`WM_NCHITTEST` → `HTMAXBUTTON`), §11.6 — полупрозрачный мини-режим.

**Решение.**
1. **Свой рендерер egui** (`cs-gpu/src/egui_renderer.rs`, ~300 строк): HLSL → DXBC (`fxc` в `build.rs`,
   байт-код также в репозитории), premultiplied-alpha смешивание в гамма-пространстве (как в браузере,
   что даёт совпадение с макетом), `register_native_texture` для превью сцены в M1.
2. **Своё Win32-окно** вместо winit/eframe: полный контроль над `WM_NCCALCSIZE`/`WM_NCHITTEST`
   (Snap Layouts), DPI Per-Monitor V2, оконной процедурой без лишнего слоя абстракции.
3. **Swapchain через DirectComposition** (`CreateSwapChainForComposition`, `WS_EX_NOREDIRECTIONBITMAP`):
   попиксельная прозрачность для мини-режима `#17181bee` без layered windows; flip-model.
4. Текст и раскладка экранов — ручная (прямоугольники + текст + `ui.interact`), а не стандартные виджеты:
   иначе отступы egui не позволяют уложиться в допуск ±2 px.

**Альтернативы.** `egui-directx11` (готовый крейт) — отстаёт от версий egui, нет контроля над
смешиванием; eframe + wgpu — второе GPU-устройство (нарушает §5.2 п.1), +3–5 МБ к бинарнику;
winit — нет штатного способа вернуть `HTMAXBUTTON` для Snap Layouts.

**Последствия.** Больше платформенного кода в `cs-app/src/platform`, но exe 5.8 МБ, старт < 0.6 с,
и один путь для будущего превью без копий. Скриншот-тесты на WARP детерминированы.
