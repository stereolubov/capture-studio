# ADR-0016 — RTMP-клиент и RTMPS через SChannel

Дата: 2026-11-04. Статус: принято для реализации M3; внешняя приёмка впереди.

## Решение

RTMP реализован в `cs-output`: простое v3-рукопожатие, исходящие чанки, инкрементальный
входящий декодер, ограниченный AMF0-кодек, connect/createStream/publish/deleteStream,
подтверждения, Ping Request/Response, серверные ограничения размера чанка.
FLV-тела H.264/AAC используются непосредственно в RTMP-сообщениях.

RTMPS использует `native-tls` 0.2, на Windows — системный SChannel. Минимум TLS 1.2;
имя сервера передаётся для SNI и проверки имени сертификата. Проверки цепочки и имени
не отключаются; откат с RTMPS на открытый RTMP не выполняется. Это позволяет использовать
системное хранилище доверия без включения отдельной TLS-библиотеки и списка CA в exe.
Альтернатива — rustls с отдельным провайдером криптографии и загрузкой корневых сертификатов.

Сетевой поток получает ограниченную очередь закодированных пакетов, не блокируя рендер.
На первом запуске сохраняется первый IDR; после переподключения накопленные пакеты
сбрасываются. При переполнении или отставании более 2 с отправка возобновляется с IDR,
после повторной отправки заголовка AVC. Переподключение — 25 попыток с задержками 2–30 с;
ошибка авторизации прекращает повторы. Ожидание между попытками прерывается остановкой.

Для первого подключения используются отдельные энкодеры трансляции и записи: CBR,
низкая задержка, без B-кадров/lookahead; звук трансляции — AAC, дорожка микшера 1.
Общий энкодер при совпадающих настройках остаётся задачей M3. Динамический CBR подключён
через NVENC reconfigure, MF ICodecAPI, AMF TargetBitrate, oneVPL Reset и OpenH264 SetOption.
Подробности политики, локальных проверок и ограничений — в отчёте M3.

Ключи сохраняются через CredWriteW, читаются через CredReadW/CredFree. В профиле остаётся
только случайная ссылка `CaptureStudio/stream/<uuid>`. Сохранение нового ключа создаёт новую
запись: старую не удаляем, поскольку на неё может ссылаться копия профиля. Автоматическая
очистка неиспользуемых записей пока не реализована.

## Проверки и ограничения

- Локальный TCP-сервер: публикация, серверный stream ID, AMF, служебные сообщения.
- Независимый FFmpeg RTMP-приёмник: H.264 с B-кадрами + AAC, 90/142 пакета без потерь;
  полученный MKV полностью декодируется. Воспроизведение: `python tools/probe_rtmp.py`.
- Недоверенный TLS-сертификат отклоняется до отправки RTMP/ключа; тестовый PKCS#12
  `tests/fixtures/localhost-untrusted.p12` содержит только синтетический ключ localhost,
  пароль `test-only`, создан специально для этого теста.
- Сервисы загружаются из `assets/services.toml` рядом с exe или из встроенного списка.
  `verified` означает доступность пресета; это не подтверждение реального эфира.
- Приёмка Twitch/YouTube, положительный RTMPS-тест с доверенным сертификатом,
  длительные прогоны, точный порог старта 1.5 с и сетевые обрывы ещё не выполнены.
- DNS, TLS, handshake и отдельная запись сокета могут задержать остановку до своих таймаутов;
  DNS системный и не имеет отдельной отмены. UI и рендер при этом не блокируются.
