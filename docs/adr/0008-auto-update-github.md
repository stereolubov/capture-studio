# ADR-0008: Автообновление из GitHub Releases (черновик)

**Контекст.** Решение заказчика (2026-10-28): код публикуется в `github.com/stereolubov/capture-studio`,
обновления — оттуда. ТЗ §18.3: автообновление — v1.x, по умолчанию выключено, проверка подписи пакета
обязательна; §16.1: сеть — только к серверам трансляции и (если включено) к серверу обновлений.

**Решение (план).**
- Проверка: `GET https://api.github.com/repos/stereolubov/capture-studio/releases/latest` — только если
  пользователь включил «Проверять обновления» (по умолчанию выкл.), не чаще раза в сутки, без телеметрии.
- Каждый релиз содержит `capture-studio-<ver>-portable.zip`, установщик и `manifest.json` с SHA-256
  файлов, подписанный **ed25519** (ключ хранится в секретах CI, публичный ключ вшит в exe).
- Скачанный пакет применяется только после проверки подписи манифеста и хэша; во время эфира/записи
  обновление не устанавливается.
- Установка: портативная версия — замена файлов через вспомогательный процесс после выхода;
  установщик — запуск нового установщика в тихом режиме.
- TLS — `rustls` (общий с RTMPS, §10.2).

**Альтернативы.** Только Authenticode — нет сертификата (см. `docs/signing.md`), и проверка зависела бы
от УЦ; сторонние фреймворки обновлений (Squirrel, Velopack) — лишний вес и свой формат.

**Последствия.** Реализация — после M5 (v1.x), инфраструктура релизов (CI, манифест) — в M5.
