# ADR-0012: собственные мультиплексоры MKV, MP4 и фрагментированного MP4

Статус: принято (2026-10-30).

## Контекст

ТЗ §10.1: контейнеры MKV (по умолчанию, не повреждается при сбое), MP4, фрагментированный MP4
(безопасен при сбое и сразу совместим с редакторами); авто-ремукс MKV → MP4; раздельные
аудиодорожки (до 6); пауза записи. Мультиплексоры — предпочтительно чистый Rust (собственный или
проверенный крейт, через ADR); FFmpeg — только отдельной DLL и только через ADR.

## Решение

Собственные мультиплексоры в `cs-output`, без внешних зависимостей:

- `mkv` — запись MKV (кластеры по ключевым кадрам, Cues, финализация); `mkv_read` — чтение для
  ремукса, в том числе обрезанного при сбое файла;
- `mp4` — ремукс MKV → MP4 с `moov` перед `mdat` (faststart), `elst` для сдвига начала звука;
  B-кадры — время декодирования восстанавливается по меткам показа, `ctts` и сдвиг в `elst`;
- `fmp4` — фрагментированный MP4 во время записи: `ftyp` + `moov` с `mvex`, затем `moof` + `mdat`
  на ключевых кадрах не реже секунды (каждый фрагмент сразу сбрасывается на диск); сдвиги показа
  B-кадров — в `trun` (версия 1, знаковые), начало звука — в `tfdt`;
- раздельные дорожки: каждая выбранная дорожка микшера — отдельная звуковая дорожка во всех трёх
  форматах.

## Альтернативы

- `mp4`/`mp4-rust`, `matroska`-крейты: либо только чтение, либо без фрагментов/`ctts`, либо
  тяжёлые зависимости; объём собственного кода невелик (~1000 строк с тестами).
- FFmpeg (`libavformat`) отдельной DLL: лишний модуль и LGPL ради трёх простых форматов.

## Последствия

- Проверено: B-кадры в MKV и MP4 — декодирование без ошибок, A/V +3…+8 мс; fMP4 — 1029 кадров,
  A/V +10 мс; принудительное завершение программы на 8-й секунде записи fMP4 оставляет
  открываемый файл на 6 с (теряется только незавершённый фрагмент); ремукс переносит все
  звуковые дорожки.
- Названия звуковых дорожек пока пишутся только в MKV.
