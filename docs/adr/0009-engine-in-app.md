# ADR-0009: Движок (оркестрация) — модуль `cs-app/src/engine`

**Контекст.** §5.3 не выделяет крейт для оркестрации: рендер-поток, источники, коллекция сцен,
история, автосохранение. §5.2 п.6 требует, чтобы в UI-коде не было логики эфира.

**Решение.** Движок — отдельный модуль `engine` в `cs-app` (корень композиции), без зависимостей от UI:
- `EngineHandle` реализует трейт `cs_core::state::Engine` — тот же интерфейс, что у мок-движка, поэтому
  UI не различает мок (`--mock-ui`, скриншот-тесты) и настоящий движок.
- Команды — ограниченная очередь `crossbeam-channel` (256); снимок `Arc<AppState>` публикуется после
  каждого тика; превью передаётся окну как SRV через `Engine::preview_handle()`.
- Редактирование сцен (`scene_ops.rs`) не зависит от GPU и покрыто модульными тестами; жест мышью —
  один шаг отмены (`Checkpoint` + промежуточные `SetItemTransform { record: false }`).
- Рендер-поток: приоритет `THREAD_PRIORITY_HIGHEST`, ожидание `CreateWaitableTimerExW(HIGH_RESOLUTION)`,
  темп по частоте холста, опоздание больше чем на кадр — «пропущено (рендер)».
- Автосохранение коллекции — в отдельном потоке через 1 с после последнего изменения, при выходе — сразу.

**Альтернативы.** Крейт `cs-engine` — добавил бы границу без пользы до появления второго потребителя
(например, бенчмарк-режима без окна в M5 — тогда модуль переедет в крейт).

**Последствия.** `cs-app` зависит от `cs-capture`/`cs-gpu` напрямую; UI-модули используют только `Engine`.
