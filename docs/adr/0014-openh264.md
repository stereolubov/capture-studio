# ADR-0014: программный H.264 — OpenH264 от Cisco, скачиваемый пользователем

Статус: принято (2026-10-30).

## Контекст

ТЗ §9.1: программный H.264 — последний резерв (OpenH264, BSD, или аналог с совместимой
лицензией; x264 — только при GPL), с явным предупреждением о нагрузке CPU. Патентные отчисления
MPEG LA за H.264 Cisco оплачивает только за **свой двоичный модуль**, причём программа должна
скачивать его на компьютер пользователя с сервера Cisco, а не поставлять в составе дистрибутива
(openh264.org/faq). Собранный из исходников OpenH264 лицензионно чист (BSD-2), но патентного
покрытия не даёт.

## Решение

- Двоичный модуль Cisco `openh264-2.6.0-win64.dll` скачивается по действию пользователя
  («Настройки → Вывод → OpenH264 → Скачать с сайта Cisco») с `https://ciscobinary.openh264.org`
  через WinHTTP (системные прокси и сертификаты, без HTTP-крейта), распаковывается из `.bz2`
  (крейт `bzip2` на чистом Rust) и кладётся в `<каталог данных>/codecs`.
- Перед подключением SHA-256 файла сверяется со списком известных сборок Cisco
  (`openh264-sys2`, функция `from_blob_path`); несовпавший файл удаляется. Подключение —
  динамическое (`libloading`), исходники OpenH264 не собираются (фича `source` выключена).
- Кадр NV12 читается из видеопамяти через staging-текстуру — единственный разрешённый путь
  GPU→CPU в записи (§4, исключение для программного энкодера) — и переводится в I420.
- Параметры: битрейт CBR/VBR или постоянный QP, период ключевых кадров = GOP, пропуск кадров
  выключен (равномерность записи важнее битрейта), постоянные ID SPS/PPS, сложность по пресету,
  CABAC для Main/High, до 4 потоков со срезами. B-кадров нет: DTS = PTS.
- При выборе энкодера показываются предупреждение о нагрузке CPU и уведомление
  «OpenH264 Video Codec provided by Cisco Systems, Inc.», которого требует Cisco.
- Цепочка: выбранный → Media Foundation → OpenH264; «Авто» — NVENC → AMF → QSV → MF → OpenH264.

## Альтернативы

- Собрать OpenH264 из исходников (фича `source`): нет патентного покрытия Cisco, нужен NASM.
- x264: GPL, несовместимо с MIT (ADR-0007).
- Программный MFT Media Foundation (H.264 Encoder MFT): есть не во всех редакциях Windows
  (N/KN), качество и скорость хуже; остаётся запасным путём аппаратного MF.
- HTTP-крейт (`ureq`, `reqwest`): лишние зависимости и своя TLS ради одного файла.

## Последствия

- Проверено: тест `openh264_gpu` скачивает модуль с сервера Cisco (хеш совпал), кодирует
  60 кадров 640×360 (по пакету на кадр, SPS/PPS в ключевых, профиль High), ffmpeg декодирует
  поток без ошибок.
- Новые зависимости: `openh264-sys2` (BSD-2), `libloading` (ISC), `sha2` и её зависимости
  (MIT/Apache-2.0), `bzip2` (MIT/Apache-2.0), `libbz2-rs-sys` (лицензия bzip2-1.0.6 —
  пермиссивная, добавлена в `deny.toml`).
- Модуль Cisco живёт в каталоге данных; удаление каталога или переход на новую версию модуля
  требуют повторной загрузки (новая версия — вместе с обновлением `openh264-sys2`).
